# ObliviOS Capability Boundaries

Each service has a narrow interface. Denied capabilities must later become
platform permission, Binder, SELinux, storage, and test policy.

| Service | Allowed inputs | Allowed outputs | Data classification | Privileges | Explicit denials | Audit events | Failure behaviour |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Network policy | Authorized typed request. | Policy decision and connection summary. | App identity/policy/network metadata. | Assigned network-policy APIs. | Packet-content inspection, arbitrary VPN config, cross-profile reads. | Policy create/change/delete and denial. | Keep last valid policy; fail closed only for explicit block. |
| Worlds/profile manager | User-mediated lifecycle or share request. | Profile state and explicit share token. | Profile metadata; profile-bound data. | Multi-user/profile APIs. | Silent cross-world access, shared clipboard by default, credential reads. | Create/switch/delete/share approval. | Abort incomplete change; preserve profiles. |
| Secure Share | User source, destination, constraints. | Time-bounded share handle. | Selected data and share metadata. | Explicit URI/content grant path. | Directory-wide grant, background export, hidden cross-world copy. | Request, approval, expiry, revoke. | Revoke incomplete grant and delete temporary handle. |
| Secure Clipboard | Explicit copy/paste and policy. | Profile-scoped expiring item. | Clipboard content for configured retention. | Clipboard-service extension. | Cross-world read, silent history. | Copy, paste, expiry, denial. | Clear expired or invalid item. |
| Notification Firewall | Notification metadata and user policy. | Allow, suppress, summarize, quarantine. | Metadata and content only with user policy. | Notification filter scope. | Default content export to AI, mutation outside policy. | Decision, match, summary, override. | Deliver when unavailable unless user selects fail closed. |
| Package installer | Signed install/update request and metadata. | Allow, deny, quarantine. | Manifest, signature, scanner findings. | Installer integration only. | Signature bypass, integrity spoofing, silent privileged install. | Scan, signature, policy, approval. | Reject invalid package; retain previous version. |
| Updater | Signed channel metadata and artifact. | Verified staged update request. | Release metadata and hashes. | Updater integration/storage. | GrapheneOS update URL, unsigned metadata, downgrade bypass, signing-key access. | Check, download, signature, install, rollback. | Reject artifact; retain verified system. |
| Backup | User-approved configuration and handles. | Encrypted artifact and restore manifest. | Data encrypted before export. | Scoped backup APIs and key references. | Plaintext cloud upload, vault export, cross-world mixing. | Create, verify, restore, delete. | Preserve original data; remove incomplete artifact. |
| Vault | Explicit credential/passkey operation. | Authenticated credential result. | Secrets and cryptographic references. | Hardware-backed credential APIs. | AI secret access, raw secret logging, plaintext backup. | Request, user auth, key-use failure. | Deny and reveal no secret material. |
| Passwords app | The user's passphrase and, if switched on, a fresh strong-biometric authentication; the fields of a login screen that the autofill framework hands over; the user's own entries and export files. | Pixels on the screen; a chip (a key icon and one line of text, ADR-191, proposed) in the strip of the system keyboard, drawn by the system from this content; fills into the field the user chose (a username and a password, after an authentication); the user's own encrypted export file; the single generic "login exists" answer of the domain index. | Secrets (passwords, notes, history); keyed hashes of the registrable domains and packages that have an account. | An app with the user's uid; Keystore keys for the hardware secret, the index and the biometric wrapper; the autofill service and credential provider service roles, once the user selects them; no platform privilege. | `INTERNET` and every network and radio permission (a host check fails the build), backup of any kind, any exported component that returns a secret, bulk reads of the vault by other apps, the screen-lock credential as an unlock, a log line with a secret, a screenshot or recents image (every window is secure), saved instance state, fuzzy domain matching, fetching a logo, a chip for any keyboard other than the system keyboard, a chip that shows a password, a dataset filter taken from the stored value. | None of its own (no account, no telemetry); failed unlocks are counted locally and only throttle. | Locked or lost secret: no fill and no secret shown; the right passphrase never opens a vault whose hardware secret is gone, and the app says so and offers an import instead of an empty vault. |
| Location Anchor | Owner's explicit toggle action; one fresh location fix captured at toggle-on time; the owner's theft-recovery override setting. | A frozen anchor fix, with bounded jitter, served through the real-provider injection point (`LocationProviderManager.setRealProvider`, see `docs/research/location-framework-api-verification.md`) in place of a live fix while ON. | The owner's own current-session location state. | Provider-injection privilege equivalent to `setRealProvider` for the four standard location providers; no network, no other app's data, no Binder/file/root/shell authority beyond that injection point. | Serving the anchor fix to the emergency-location path (always real, unconditional); serving it to the theft-recovery lookup unless the owner's explicit override is enabled; any persisted, timestamped record of on/off transitions; any API surface exposing past anchor state. | None, by design — see `docs/superpowers/specs/2026-08-12-location-anchor-design.md` and ADR-037: a persisted history is a liability against the exact adversary this feature defends against, not an oversight. | Mid-session service restart fails closed to no-fix rather than passing through a real fix; reboot preserves the prior on/off state and anchor point without creating a new record. |
| Duress Unlock | Owner's explicit setup action (decoy profile creation, separate challenge PIN); the exact credential typed at the primary keyguard on every unlock attempt. | Either a normal unlock into the real profile, or — on a decoy-credential match — a direct foreground switch into the pre-provisioned, isolated decoy profile with the real profile's processes frozen (user 0 cannot be stopped, so its storage stays unlocked; ADR-304). | The owner's own credential-match outcome and current foreground-profile state; no third-party data. | Primary-keyguard credential-check hook (dual-credential comparison); real-profile freeze authority (`ActivityManagerInternal.quiesceUserApps`, `RealUserQuiescer`), see `docs/research/duress-unlock-api-verification.md`. | Nested decoys; any persisted record of which credential was entered, when, or how often; counting a successful decoy match as a failed real-profile attempt (except the real profile's Weaver count, ADR-304); auto-generated decoy content; any indicator visible while the decoy profile is foregrounded. | None, by design — a decoy-unlock event must be indistinguishable, after the fact, from a normal unlock; see `docs/superpowers/specs/2026-08-12-duress-unlock-design.md`. | A credential-check failure against both real and decoy profiles counts as one failed attempt against each of them (forensic review P1); a hook failure or crash fails closed to today's single-credential unlock path and never reveals the decoy profile; reboot never preserves which profile was last shown — every unlock is decided fresh. |
| Exit daemon (`Proposed`, ADR-184, ADR-186 and ADR-187; built and packaged, in `lynx` image `2026102301` (`IMG-013`), flashed 2026-10-23) | Packets that the kernel delivers into its tun interface, among them the DNS queries of masked uids and the packets to the fake address range; the mask list file of the image; the uid classes and per-company overrides from the exit app; the owner uid of a flow from `sock_diag`; typed messages from the exit app (state query, uid classes, per-company overrides, "Hide again" for a promoted company, set the memory cap, refresh the circuits of an app, shutdown); the Tor directory and the relays, as a network client. | Packets written to the tun; connections through the Tor network; to the exit app only: the name of its tun interface, an up or down state and counts of failed connections per uid and company id and the companies that the speed guard passes on to an app for 30 minutes (uid and company id; never a host name). | Destinations and timing of each app's connections; sensitive because it reveals app usage and, with the masked class of ADR-181, which listed hosts each app contacts. | `CAP_NET_ADMIN` only; the tun device with `TUNSETIFF` and `TUNGETIFF`; the `sock_diag` netlink socket; ordinary internet sockets as its own uid, which stays outside every preference; the control channel. | Any framework permission, any Binder service other than the control channel, a routing-table or netfilter write, a socket mark, `should_protect` for an app (it lets an app leave the tunnel), reading app data or storage, writing a destination or host name to storage or a log, telemetry, a relay operated by the project, serving any caller other than the exit app. | Start, stop and restart; bootstrap complete or failed; a circuit refresh requested; a refused quota request. Counts only, never destinations: the failure reports (uid, company id, count) travel with the answer to a state query, and a refused request gets an error code with its sequence number. A started daemon prints one fixed line when it is up. | Fail closed for apps set to Tor (no network, as ADR-178); never fall back to Direct; refuse a flow that cannot be attributed to a uid instead of giving it a shared key; restart by `init` after a panic (the build aborts on panic). |
| Route helper (`Proposed`, ADR-186; built and packaged, in `lynx` image `2026102301` (`IMG-013`), flashed 2026-10-23) | Typed route specifications from the exit app (an interface name, two lists of uid ranges of at least 10000, an optional network id; the tun addresses are constants of the rule language). | Rules in the priority band `13100` to `13999`, one default route in table `4747`, the address and up state of the tun interface; an acknowledgement or an error code to the exit app. | The uid ranges of apps that are masked or set to Tor (no destination, no packet, no name). | `CAP_NET_ADMIN`; `netlink_route_socket` with `nlmsg_write` limited by `allowxperm` to the rule, route, address and link messages; the control socket from `init`. | Any internet or Unix socket other than the control socket, the Tor network, a rule outside the band or the table, a uid below 10000, reading app data, storage, a name or a packet, serving any caller other than the exit app, a netfilter write. | Applied, cleared, refused (with the error code). Counts only. | On a crash `init` restarts it and the exit app sends the specification again; rules stay in the kernel meanwhile, and a missing tun makes the steering rules fall through, which is the measured behaviour (`MSK-008`). |
| Exit app (`Proposed`, ADR-184, ADR-186 and ADR-187; built and packaged, in `lynx` image `2026102301` (`IMG-013`), flashed 2026-10-23) | The user's choice per app (Direct, Tor or an own profile) and the masked-destinations setting; the status messages of the daemon; the package list. | The `OemNetworkPreferences`; the registered network and its link properties; notifications and the Settings rows; typed messages to the daemon (uid classes, overrides) and to the route helper (the route specification). | The user's per-app exit choice and the pairs (package, company id) of the hosts the user chose to show an address to, in device-protected storage (a company id is stable: `privacy/exit/mask-company-ids.tsv`, ADR-186); per-app counts of failed connections, kept in RAM only. | `NETWORK_FACTORY` and `CONTROL_OEM_PAID_NETWORK_PREFERENCE` (signature level), platform-signed; no capability, not `NETWORK_STACK`, no tun, no `sock_diag`. | Creating a tun, reading a flow or a packet, looking up uids, contacting the Tor network, storing destinations, accepting a preference change from another app, any network request of its own. | Preference changed (app, class), network registered or unregistered, failure notification shown. | If the daemon is down, mark the network down and show the message of ADR-178; keep the stored choices and never clear a preference silently; re-apply the preferences at boot before apps start, because the platform does not persist the preference map (finding F11 of the review). |
| Compartments platform closures (`Proposed`, ADR-173, ADR-174, ADR-175, ADR-179; patches in `privacy/linkability` and `privacy/identity-surface`, built into `lynx` images up to `2026102101`) | The caller's uid and package, the permissions it holds (`USE_LOOPBACK_INTERFACE`, a paste grant), the three global settings `oblivios_loopback_open`, `oblivios_settings_open` and `oblivios_settings_real_packages`. | A refused loopback, broadcast or multicast datagram; a settings read that answers unset; a clipboard answer that is the same for every clip; a rounded vibrator calibration; hidden device colour and country; a per-app hash of `MediaStore.getVersion`; hidden `ro.boot.*` unit properties; sensor readings with the bias folded in. | The values themselves are the identifiers of the device; the policy holds no new data. | No new permission, capability or endpoint. `USE_LOOPBACK_INTERFACE` changes from normal to dangerous (a runtime permission); the three settings switches are Global keys and need `WRITE_SECURE_SETTINGS` to change. | A new service, a new exported component, any logging of what an app read or was denied, a per-app policy store (not built; the switches are all-or-nothing or per package name), and a weakening of the loopback, settings or clipboard checks for system uids. | The drops of the BPF loopback program in the metrics ring buffer; no per-app log. | Fail closed for the denied value: an app that needs a hidden key sees it unset, and the three switches restore the stock behaviour without a reflash. |
| Recovery | Verified local recovery action. | Signed-system restoration status. | Recovery metadata, never decrypted content. | Recovery environment APIs. | Unsigned boot, rollback bypass, arbitrary extraction. | Verification, restore/failure, reset. | Halt untrusted flow; show safe options. |
| AI broker | Minimized facts and explicit user intent. | Explanation, preview, typed action request. | Structured incident/action facts. | No direct privileged authority. | Root, shell, arbitrary Binder, arbitrary file reads, direct policy mutation, package-manager/vault/backup/network authority. | Prompt class, tool request, denial, approved handoff. | Refuse safely; never execute unvalidated request. |
| AirPods compatibility service | Bonded accessory identity, declared model/firmware, bounded Bluetooth messages, connection events, owner-enabled location snapshot, typed control ID. | Normalized component status, typed supported control result, latest local record, one allow-listed browser intent, one owner-initiated sanitized diagnostic export file; a Settings-facing device-settings provider service and an icon content provider, each reachable only by holders of `BLUETOOTH_PRIVILEGED` (spec `2026-09-29-airpods-settings-ui-design.md` §8). | Accessory technical metadata and owner-private precise location. | Bluetooth connection and bounded scanning; profile-bound encrypted storage; a location snapshot only when the owner enabled local finding; one non-SDK API exemption scoped to this service alone; `BLUETOOTH_PRIVILEGED` only if the chosen provider-registration route needs it (open decision O2, to be justified and reviewed). | Unknown-device mapping, arbitrary Bluetooth scanning, arbitrary web URLs, Apple credentials/cookies/attestation tokens, direct Apple Find My network access, AI export, telemetry, coordinate logging, device-wide Vendor ID spoofing, Xposed/root/general hooking frameworks, arbitrary Binder, shell, or filesystem access. | Enable, disable, clear, control request, control result, and failure reason (non-coordinate). | No fabricated state; retain the last valid component record when safe; mark current state unavailable; never block Bluetooth audio or ordinary SystemUI. |
| Data Map collector | DNS lookup events (uid, hostname, resolved address count, time) and TCP connect events (uid, destination address, port, time) from `NetdEventListenerService`; a uid's foreground or background state; the user's retention choice; the read-only classifier file; the read-only address file (ADR-161: hosting country, city, ASN, operator and anycast flag of an address). | `DataMapEntry` aggregates, derived `DataMapLink` records and the classifier's `DataMapRelation` records, to the holder of `READ_DATA_MAP`, for the calling user only. | Technical metadata about destinations; sensitive because it reveals app usage. | One callback slot in `NetdEventListenerService`; read of a uid's process importance; own per-user file under the credential-encrypted system directory, only while history is on (and the server places of a row only when the user chose to keep them). | Packet content, URLs, query strings, bytes per destination, keeping an address after its lookup, own network requests, export in any form, cross-user reads, access by any app other than `DataMapApp`, raw-event access for the AI broker, any disk write while history is off, inclusion in backup, fetching a list or update. | History on or off, duration changed, data cleared, collecting on or off. | Drop events on error or overload; never block or fail resolution or connections; deny reads without the permission; start empty on a corrupt file. |
| Data Map app | The snapshot of the collector for the calling user; the user's touches; the package list, icons and labels of installed apps. | Pixels on the screen; the user's settings choices back to the collector; one new text file, only when the user confirms the dialog of Settings, through the system document picker (ADR-189). | Technical metadata about destinations; the names and icons of installed apps. | `READ_DATA_MAP`; `QUERY_ALL_PACKAGES` for icons and labels only. | `INTERNET` and any other network permission, any service, receiver, provider or alarm, writing files of its own or sharing or exporting any data other than the one user-driven file of ADR-189 (no storage permission, no share target, nothing written at any other time), reading any app's data, shipping any app's logo as a file (company logos only as ADR-159 allows). | None of its own; settings changes are audited by the collector. | Show an empty map and say so when the service is unavailable; an app with no usable icon shows its initials. |
| Sensor service identity fold | Uncalibrated sensor events from the sensors HAL (type, three readings, three bias values) and the uid of the receiving connection. | The same event with the bias folded into the readings and reported as zero, for every app uid (`uid % AID_USER_OFFSET >= AID_APP_START`). | Sensor readings (motion and orientation, sensitive). | One transformation in `SensorEventConnection::sendEvents` under the existing `mConnectionLock`; no new permission, service, IPC or file `[assumption: the patch is written but neither built nor run; the host test IDS-001 proves the arithmetic and the uid rule, not the integration in sendEvents]`. | Any other change of a reading, noise injection, a change for a native daemon or a platform uid, storage, logging or transmission of events. | None; the change is silent by design. | A bias that is not finite is dropped and the readings stay as delivered; an event is never dropped. |
| Unit boot properties | `ro.boot.cdt_hwid`, `ro.boot.hardware.devcfg`, `ro.boot.hardware.pcbcfg`, `ro.boot.hw.soc.id`, `ro.boot.vbmeta.device`, set by init from the kernel command line `[verified-in-source: private/property_contexts, comment above the ro.boot. prefix]`. | Reads by every domain except `appdomain`, `app_zygote` and `native_app_zygote` (SELinux type `unit_boot_prop`); `shell` is in `appdomain`. | Device-specific identifiers. | `get_prop({ domain -appdomain -app_zygote -native_app_zygote }, unit_boot_prop)`; no allow rule for an app `[measured: compiled (IDS-002); on the lynx image 2026101406 the five names are absent for two apps and for an app-zygote preload (IDS-003, IDS-009); stallion not run]`. | Any read by an app, any write by a ObliviOS component, any copy into a log, snapshot or export by a ObliviOS component. | SELinux denials of the type in `logcat -b all`. | An app that reads one gets an empty value; every other domain is unchanged. |
