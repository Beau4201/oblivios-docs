# FreeholdOS Capability Boundaries

Each service has a narrow interface. Denied capabilities must later become
platform permission, Binder, SELinux, storage, and test policy.

| Service | Allowed inputs | Allowed outputs | Data classification | Privileges | Explicit denials | Audit events | Failure behaviour |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Guardian sensor | Approved Android event subscriptions; a UID's current process importance (foreground/background), needed to scope background-only events. | `GuardianEventV1` only. | Minimized technical metadata. | Read declared event fields; read a UID's live process importance only — no usage-stats history, app-usage duration, or data-usage query surface, even though the underlying platform permission also exposes those. | Personal content, microphone audio, camera frames, arbitrary files, historical app-usage statistics. | Source, rejection, subscription error. | Drop invalid event; never block foreground app. |
| Guardian detection | Valid event, local rule, local baseline. | `GuardianIncidentV1`, bounded owner-visible evidence summary, and a bounded `GuardianMeaningfulChangeV1` derived only after a registered rule outcome. | Technical metadata and derived risk. | Local retention-bounded incident store. | Direct remediation, network mutation, arbitrary package control, cloud/AI evidence export, meaningful-change derivation without a registered rule outcome. | Rule version, score, suppression, incident, retention deletion. | Preserve event; no automatic restriction. |
| Guardian remediation | Registered incident and `GuardianRemediationV1`. | Typed result, verification, and `GuardianActiveProtectionV1` state written only after the existing registered action and verification path. | Action and minimal package/policy state. | Action-specific framework call; device-wide package-list visibility (`QUERY_ALL_PACKAGES`), needed only to read/act on a target app's own permission grant state through the standard `PackageManager` API — not a package-content, install, or usage-data query surface. | Unknown ID, shell, root, arbitrary Binder, direct database edit, active-protection state written outside the verified action path, use of package-list visibility for any purpose other than the registered action's own target-app permission check. | Preconditions, action, verification, rollback, Undo. | No change on precondition failure; rollback failed verified action. |
| Guardian Overview resolver | Bounded local `GuardianActiveProtectionV1` and `GuardianMeaningfulChangeV1` summary records. | Minimized `GuardianOverviewEntry`/`GuardianOverviewSnapshot` owner-visible entries. | Minimized derived summary data. | Read-only local summary-store access. | Direct remediation, package-manager, network-policy, shell, root, Binder, file, AI, vault, backup, and cloud authority. | None beyond the source detection/remediation audit events; the resolver performs no independent write. | Omit the affected entry; never fabricate or guess state. |
| Network policy | Authorized typed request. | Policy decision and connection summary. | App identity/policy/network metadata. | Assigned network-policy APIs. | Packet-content inspection, arbitrary VPN config, cross-profile reads. | Policy create/change/delete and denial. | Keep last valid policy; fail closed only for explicit block. |
| Worlds/profile manager | User-mediated lifecycle or share request. | Profile state and explicit share token. | Profile metadata; profile-bound data. | Multi-user/profile APIs. | Silent cross-world access, shared clipboard by default, credential reads. | Create/switch/delete/share approval. | Abort incomplete change; preserve profiles. |
| Secure Share | User source, destination, constraints. | Time-bounded share handle. | Selected data and share metadata. | Explicit URI/content grant path. | Directory-wide grant, background export, hidden cross-world copy. | Request, approval, expiry, revoke. | Revoke incomplete grant and delete temporary handle. |
| Secure Clipboard | Explicit copy/paste and policy. | Profile-scoped expiring item. | Clipboard content for configured retention. | Clipboard-service extension. | Cross-world read, silent history, Guardian content export. | Copy, paste, expiry, denial. | Clear expired or invalid item. |
| Notification Firewall | Notification metadata and user policy. | Allow, suppress, summarize, quarantine. | Metadata and content only with user policy. | Notification filter scope. | Default content export to Guardian/AI, mutation outside policy. | Decision, match, summary, override. | Deliver when unavailable unless user selects fail closed. |
| Package installer | Signed install/update request and metadata. | Allow, deny, quarantine. | Manifest, signature, scanner findings. | Installer integration only. | Signature bypass, integrity spoofing, silent privileged install. | Scan, signature, policy, approval. | Reject invalid package; retain previous version. |
| Updater | Signed channel metadata and artifact. | Verified staged update request. | Release metadata and hashes. | Updater integration/storage. | GrapheneOS update URL, unsigned metadata, downgrade bypass, signing-key access. | Check, download, signature, install, rollback. | Reject artifact; retain verified system. |
| Backup | User-approved configuration and handles. | Encrypted artifact and restore manifest. | Data encrypted before export. | Scoped backup APIs and key references. | Plaintext cloud upload, vault export, cross-world mixing. | Create, verify, restore, delete. | Preserve original data; remove incomplete artifact. |
| Vault | Explicit credential/passkey operation. | Authenticated credential result. | Secrets and cryptographic references. | Hardware-backed credential APIs. | Guardian/AI secret access, raw secret logging, plaintext backup. | Request, user auth, key-use failure. | Deny and reveal no secret material. |
| Location Anchor | Owner's explicit toggle action; one fresh location fix captured at toggle-on time; the owner's theft-recovery override setting. | A frozen anchor fix, with bounded jitter, served through the real-provider injection point (`LocationProviderManager.setRealProvider`, see `docs/research/location-framework-api-verification.md`) in place of a live fix while ON. | The owner's own current-session location state. | Provider-injection privilege equivalent to `setRealProvider` for the four standard location providers; no network, no other app's data, no Binder/file/root/shell authority beyond that injection point. | Serving the anchor fix to the emergency-location path (always real, unconditional); serving it to the theft-recovery lookup unless the owner's explicit override is enabled; any persisted, timestamped record of on/off transitions; any API surface exposing past anchor state. | None, by design — see `docs/superpowers/specs/2026-08-12-location-anchor-design.md` and ADR-037: a persisted history is a liability against the exact adversary this feature defends against, not an oversight. | Mid-session service restart fails closed to no-fix rather than passing through a real fix; reboot preserves the prior on/off state and anchor point without creating a new record. |
| Duress Unlock | Owner's explicit setup action (decoy profile creation, separate challenge PIN); the exact credential typed at the primary keyguard on every unlock attempt. | Either a normal unlock into the real profile, or — on a decoy-credential match — a direct foreground switch into the pre-provisioned, isolated decoy profile with the real profile explicitly force-stopped. | The owner's own credential-match outcome and current foreground-profile state; no third-party data. | Primary-keyguard credential-check hook (dual-credential comparison); real-profile force-stop authority equivalent to `UserController.stopUser` (`INTERACT_ACROSS_USERS_FULL`), see `docs/research/duress-unlock-api-verification.md`. | Nested decoys; any persisted record of which credential was entered, when, or how often; counting a successful decoy match as a failed real-profile attempt; auto-generated decoy content; any indicator visible while the decoy profile is foregrounded. | None, by design — a decoy-unlock event must be indistinguishable, after the fact, from a normal unlock; see `docs/superpowers/specs/2026-08-12-duress-unlock-design.md`. | A credential-check failure against both real and decoy profiles counts as one normal failed attempt against the real profile only; a hook failure or crash fails closed to today's single-credential unlock path and never reveals the decoy profile; reboot never preserves which profile was last shown — every unlock is decided fresh. |
| Recovery | Verified local recovery action. | Signed-system restoration status. | Recovery metadata, never decrypted content. | Recovery environment APIs. | Unsigned boot, rollback bypass, arbitrary extraction. | Verification, restore/failure, reset. | Halt untrusted flow; show safe options. |
| AI broker | Minimized facts and explicit user intent. | Explanation, preview, typed action request. | Structured incident/action facts. | No direct privileged authority. | Root, shell, arbitrary Binder, arbitrary file reads, direct policy mutation, package-manager/vault/backup/network authority. | Prompt class, tool request, denial, approved handoff. | Refuse safely; never execute unvalidated request. |
| AirPods compatibility service | Bonded accessory identity, declared model/firmware, bounded Bluetooth messages, connection events, owner-enabled location snapshot, typed control ID. | Normalized component status, typed supported control result, latest local record, one allow-listed browser intent, one owner-initiated sanitized diagnostic export file; a Settings-facing device-settings provider service and an icon content provider, each reachable only by holders of `BLUETOOTH_PRIVILEGED` (spec `2026-09-29-airpods-settings-ui-design.md` §8). | Accessory technical metadata and owner-private precise location. | Bluetooth connection and bounded scanning; profile-bound encrypted storage; a location snapshot only when the owner enabled local finding; one non-SDK API exemption scoped to this service alone; `BLUETOOTH_PRIVILEGED` only if the chosen provider-registration route needs it (open decision O2, to be justified and reviewed). | Unknown-device mapping, arbitrary Bluetooth scanning, arbitrary web URLs, Apple credentials/cookies/attestation tokens, direct Apple Find My network access, Guardian/AI export, telemetry, coordinate logging, device-wide Vendor ID spoofing, Xposed/root/general hooking frameworks, arbitrary Binder, shell, or filesystem access. | Enable, disable, clear, control request, control result, and failure reason (non-coordinate). | No fabricated state; retain the last valid component record when safe; mark current state unavailable; never block Bluetooth audio or ordinary SystemUI. |
| Data Map collector | DNS lookup events (uid, hostname, resolved address count, time) and TCP connect events (uid, destination address, port, time) from `NetdEventListenerService`; a uid's foreground or background state; the user's retention choice; the read-only classifier file; the read-only address file (ADR-161: hosting country, city, ASN, operator and anycast flag of an address). | `DataMapEntry` aggregates, derived `DataMapLink` records and the classifier's `DataMapRelation` records, to the holder of `READ_DATA_MAP`, for the calling user only. | Technical metadata about destinations; sensitive because it reveals app usage. | One callback slot in `NetdEventListenerService`; read of a uid's process importance; own per-user file under the credential-encrypted system directory, only while history is on (and the server places of a row only when the user chose to keep them). | Packet content, URLs, query strings, bytes per destination, keeping an address after its lookup, own network requests, export in any form, cross-user reads, access by any app other than `DataMapApp`, raw-event access for Guardian or the AI broker, any disk write while history is off, inclusion in backup, fetching a list or update. | History on or off, duration changed, data cleared, collecting on or off. | Drop events on error or overload; never block or fail resolution or connections; deny reads without the permission; start empty on a corrupt file. |
| Data Map app | The snapshot of the collector for the calling user; the user's touches; the package list, icons and labels of installed apps. | Pixels on the screen; the user's settings choices back to the collector. | Technical metadata about destinations; the names and icons of installed apps. | `READ_DATA_MAP`; `QUERY_ALL_PACKAGES` for icons and labels only. | `INTERNET` and any other network permission, any service, receiver, provider or alarm, writing files of its own, sharing or exporting any data, reading any app's data, shipping any app's logo as a file (company logos only as ADR-159 allows). | None of its own; settings changes are audited by the collector. | Show an empty map and say so when the service is unavailable; an app with no usable icon shows its initials. |
| Sensor service identity fold | Uncalibrated sensor events from the sensors HAL (type, three readings, three bias values) and the uid of the receiving connection. | The same event with the bias folded into the readings and reported as zero, for every app uid (`uid % AID_USER_OFFSET >= AID_APP_START`). | Sensor readings (motion and orientation, sensitive). | One transformation in `SensorEventConnection::sendEvents` under the existing `mConnectionLock`; no new permission, service, IPC or file `[assumption: the patch is written but neither built nor run; the host test IDS-001 proves the arithmetic and the uid rule, not the integration in sendEvents]`. | Any other change of a reading, noise injection, a change for a native daemon or a platform uid, storage, logging or transmission of events. | None; the change is silent by design. | A bias that is not finite is dropped and the readings stay as delivered; an event is never dropped. |
| Unit boot properties | `ro.boot.cdt_hwid`, `ro.boot.hardware.devcfg`, `ro.boot.hardware.pcbcfg`, `ro.boot.hw.soc.id`, `ro.boot.vbmeta.device`, set by init from the kernel command line `[verified-in-source: private/property_contexts, comment above the ro.boot. prefix]`. | Reads by every domain except `appdomain`, `app_zygote` and `native_app_zygote` (SELinux type `unit_boot_prop`); `shell` is in `appdomain`. | Device-specific identifiers. | `get_prop({ domain -appdomain -app_zygote -native_app_zygote }, unit_boot_prop)`; no allow rule for an app `[measured: compiled (IDS-002); on the lynx image 2026101406 the five names are absent for two apps and for an app-zygote preload (IDS-003, IDS-009); stallion not run]`. | Any read by an app, any write by a FreeholdOS component, any copy into a log, snapshot or export by a FreeholdOS component. | SELinux denials of the type in `logcat -b all`. | An app that reads one gets an empty value; every other domain is unchanged. |
