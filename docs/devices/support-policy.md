# ObliviOS Device Support Policy

## Supported-device entry gate

A device is supported only with verified upstream device source, current OEM firmware and driver coverage, a monthly update path, signed factory-image and OTA procedures, locked-bootloader verification, recovery validation, and evidence for emergency/radio functions, peripherals, accessibility, and retirement/migration policy. A booting image alone is not support.

Support ends when ObliviOS cannot provide current security updates or maintain required device-specific code. Retirement requires a public support-end date, a final safe update where possible, and a migration path to a supported Pixel.

## Pixel 7a bring-up sequence

1. Store device serial only in protected operations records, never this repo.
2. Verify retail firmware/build identifier and OEM unlocking status.
3. Build and boot a test-key development image with an unlocked bootloader.
4. Capture boot, radio, Wi-Fi, camera, biometrics, and crash evidence.
5. Build a release-key factory image and verify the ObliviOS AVB public key.
6. Complete bootloader relocking only after release-key validation and verify a clean boot.
7. Test OTA, rollback rejection, interrupted-update recovery, reset, and restore.
8. Run the carrier, emergency, hardware, accessibility, performance, and app matrix.

## Validation-matrix linkage

The authoritative test cases are in
`docs/quality/validation-matrix.md`:
`LYNX-001` through `LYNX-020` cover trust, install, update, recovery, reset,
backup, mobile service, connectivity, hardware, Android Auto, and accessibility;
`PERF-001` through `PERF-008` define the Pixel 7a performance measurements.
Every `lynx` support claim requires the matching case evidence and a signed
device record. A blocked, unrun, failed, or waived case is not device-support
evidence.

## Newer Pixel onboarding record

Every candidate requires codename, upstream branch/tag, OEM support end, source/vendor acquisition and verification method, build target, firmware baseline, known issues, signed-image evidence, recovery evidence, validation-matrix results, and release decision. ObliviOS does not claim a device generation supported until every listed model passes its own record.
